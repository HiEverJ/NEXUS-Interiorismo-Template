Your studio, your materials, your story.

A single-page HTML template for interior architecture studios. This guide covers the files you receive, what to replace and how to publish them.

1. Open the template

Extract the ZIP and open index.html in a modern browser. Use a text editor to edit the files. No installation or build command is necessary. Preview through your editor’s local web server when checking hosting behavior.

This is an HTML template for users comfortable editing HTML and CSS. It is not a WordPress theme or a visual page builder. Hosting, domains, a CMS, email delivery and installation services are not included.

2. Replace the demonstration content

  1. Edit the brand name, page title, meta description, Open Graph text and favicon in index.html.
  2. Replace the hero heading and description. Keep the first paragraph short and explain the work your studio actually does.
  3. Replace all project names, locations, service descriptions and footer details. The included projects and material descriptions are illustrative, not verified descriptions of the stock photographs.
  4. Replace studio@example.com in the visible email text and in href="mailto:studio@example.com". This opens the visitor’s email app; it does not send a message automatically. A real form requires a separate endpoint or form service.

3. Add your images

The buyer package uses a local SVG placeholder. Stock photography visible in the working demo is not bundled. Add your images under assets/img/ and update each image’s src and descriptive alt text.

If adding responsive variants, supply srcset with actual image widths (for example, 480w, 800w and 1200w) and a matching sizes value. Never leave the old demo URLs in a srcset after changing src. The hero loads first; other images use lazy loading. CSS reserves their display areas.

For the material scene, reposition each detail using its percentage top and left. Use align-right for points on the right and align-above for points near the bottom. Verify open cards stay inside your image. Below 993px, these points become a list of disclosures below the photo.

The demo’s five photos are remote Unsplash references. Fonts are optional remote Google Fonts references (Prata and DM Sans). No third-party image or font files are included, and no rights to those resources are granted by this template. Obtain appropriate resources for your own publication. Remove the Google Fonts links if you want to use the included system-font fallbacks without external requests.

4. Change colors and typography

The original compiled styles are in scss/main.css. The current responsive and accessibility layer is scss/enhancements.css, loaded second. Edit its :root and [data-theme="light"] palettes to change colors.

For advanced Sass editing, original sources start at scss/main.scss. With Dart Sass installed, run sass scss/main.scss scss/main.css. Keep enhancements.css loaded after the compiled file. Sass is optional and is not bundled. Preserve readable contrast when changing palettes.

5. Navigation and controls

  • The desktop sidebar stays visible. The mobile Menu button opens section links. Escape closes the menu and returns focus; selecting a link moves focus to the section.
  • The Light theme control follows the system initially and remembers a valid user choice when storage is available. Blocked storage does not prevent navigation.
  • Material summaries work with click, touch, Enter and Space. Escape closes an open detail when JavaScript is available. Native disclosures also work without JavaScript.
  • The project gallery accepts horizontal scrolling, touch swipes and previous/next buttons. Focus the gallery and use Left/Right, Home or End. Buttons disable at the boundaries.
  • Reduced-motion preferences remove animation. Without JavaScript, section links and material disclosures remain usable; the gallery still scrolls natively.

6. Publish and check

  1. Upload index.html, assets/ and scss/ together to a static web host. Preserve their relative paths and filename capitalization.
  2. Use your final domain in any canonical link and social-sharing image metadata you add. These domain-specific values are intentionally not fabricated.
  3. Test at 320, 360, 768, 992, 1024 and 1440px widths, in portrait and landscape, both palettes and at 200% zoom. Check keyboard navigation and reduced motion.
  4. Check the email link with your actual address. Check every image, open material card and gallery boundary on the deployed URL.
  5. Run HTML, accessibility and performance checks on the deployed site with final images. No Lighthouse score, accessibility certification or fixed frame rate is promised.

7. Troubleshooting

No styling: verify both CSS files exist at their referenced paths. No photos: replace the placeholders or check external network access in the demo. No remembered theme: private browsing or storage restrictions may prevent persistence; the control still works. Email does not open: configure an email app or copy the displayed address. Material text does not match the photo: update the demo descriptions and point positions for your own scene.

For support, use the seller’s contact on your purchase receipt or product listing. Include the template version, browser, viewport size, steps and a screenshot. The purchase license is provided by your store/seller; this guide does not add license permissions.
